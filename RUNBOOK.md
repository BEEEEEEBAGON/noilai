# RUNBOOK — running the experiments on Kaggle by hand

The assistant's machine has no Kaggle token and cannot reach `www.kaggle.com` or `huggingface.co`
(BLOCKED.md 1–3), so every GPU, TPU, hub-dependent and API session is launched by the author in
the Kaggle web UI, and the results come back as a private Kaggle dataset. Everything below is what
the repository already does: the notebooks are generated by `scripts/kaggle_build_notebooks.py`
(README "Run the evaluations (cloud kit)" and "Running from a private repository"), the run driver
is `scripts/kaggle_run_plan.py`, the plans are `configs/run_plan.yaml` (pre-registered, never edited
for exploratory work) and `configs/run_plan_exploratory.yaml` (dev-only). Kaggle UI labels are given
as they read in 2026; where a label may have moved it is marked "(as of 2026)". In every notebook the
**first code cell (the parameters cell) is the only cell to edit**; nothing prompts for input.

## 0. One-time setup

1. **Who holds the accounts (DD 11.2).** Kaggle, Hugging Face, Google and Groq require users to be 18
   or older (Kaggle and Groq: `minimum_age` still `null` in `configs/models.yaml`, to be read off their
   terms). If the author is under 18 at run time, an eligible adult collaborator opens and holds every
   account whose terms require it; no account is ever opened with a misstated age. Decide the ROLE
   string that every manifest will record (`ACCOUNT_HOLDER_ROLE`, e.g. `"author"` or
   `"adult collaborator"`; never a name) and record the age findings in `configs/models.yaml`
   (`terms.minimum_age`) and `docs/RISKS.md` through the assistant.
2. **Kaggle phone verification.** kaggle.com → profile picture → **Settings** → section **Phone
   Verification** → **Verify phone** (SMS code). Without it the notebook editor offers no GPU/TPU
   accelerator and the **Internet** toggle stays off.
3. **Hugging Face gated access.** Signed in on huggingface.co, open each gated repository the panel
   uses and click **Agree and access repository** (Gemma: accept the Gemma Terms once per account;
   Llama 3.1: Meta's form, approval takes hours to days): `google/gemma-3-1b-it`, `google/gemma-3-4b-it`,
   `google/gemma-3-12b-it`, `google/gemma-4-e2b-it`, `google/gemma-4-e4b-it`, `google/gemma-4-12b-it`
   (the Gemma 4 ids are `[UNCERTAIN: verify]` in `configs/models.yaml`; fix the id if the page does not
   exist), `meta-llama/Llama-3.1-8B-Instruct`, `Viet-Mistral/Vistral-7B-Chat`. Then **Settings → Access
   Tokens → Create new token**, type *Read* (as of 2026 the fine-grained form has a box "Read access
   to contents of all public gated repos you can access"; tick it). Copy the token once into the
   Kaggle Secret `HF_TOKEN` (step 7); it is never pasted into a cell.
4. **Private dataset `noilai-release`** (the frozen `data/release/v0.3/` tree; the test split is
   gated, so the dataset is private forever). kaggle.com → **Datasets → + New Dataset** → **Upload** →
   drag the folder `v0.3` (so that the dataset holds `v0.3/manifest.json`, `v0.3/noilai_dev.jsonl`,
   `noilai_test.jsonl`, `noilai_main.jsonl`, `noilai_core.jsonl`, `noilai_c2.jsonl`, `attested.jsonl`;
   a flat upload of those files also works: cell (d) accepts either layout) → **Dataset Title**
   `noilai-release` → check that the visibility reads **Private** (the default as of 2026) → **Create**.
   Leave out `manifest_private.json` (it carries the build seed and the canary GUID; the gate verifies
   the canary against `canary_sha256` of the public manifest without it) and the sealed split
   (`data/release/sealed/`, which no notebook may ever read). The derived files (`pilot_t1_200`,
   `noilai_api_para300`, `noilai_reasoning500`, `noilai_bf16_200`, `noilai_scope500`, the two
   exploratory dev sets) are NOT uploaded: cell (d) materializes them from the frozen files with the
   plan's seeds. CLI alternative from the author's machine (needs a token, step 7):
   `kaggle datasets init -p data/release` → edit `data/release/dataset-metadata.json` (`"id":
   "<kaggle-user>/noilai-release"`) → `kaggle datasets create -p data/release --dir-mode zip`.
5. **Private dataset `noilai-bundle`** (the code, pinned to a commit). On the author's machine, on the
   branch to run (`make bundle` bundles `main`; for another branch run the same two commands with its
   name and set `REPO_REF` to it): `make bundle` → `dist/noilai-main.bundle` and
   `dist/noilai-main.bundle.commit`; then exactly as README "Running from a private repository":
   `kaggle datasets init -p dist` (first time; edit `dist/dataset-metadata.json`: `"id":
   "<kaggle-user>/noilai-bundle"`, `"title": "noilai-bundle"`), `kaggle datasets create -p dist
   --dir-mode zip` (first time), `kaggle datasets version -p dist -m "code @ $(cat
   dist/noilai-main.bundle.commit)"` (every later change). Without the CLI: **+ New Dataset → Upload**
   the file `dist/noilai-main.bundle`, title `noilai-bundle`; later **Dataset page → ⋮ (three dots, as
   of 2026) → New Version** with the new bundle. Rebuild and re-upload the bundle after every commit
   you want on Kaggle (the gate file `experiments/gates.yaml`, the pins in `configs/models.yaml` and
   the plans travel in it).
6. **Private dataset `noilai-runs`** (item-level outputs, manifests, the API ledger and the compute
   log). Nothing to upload: the first session creates it (cell (g) of the GPU notebook with
   `CREATE_DATASET = True`, or the CPU recipe of §3). Every later session attaches it as an input and
   adds a version after every model; a version is a full snapshot of what the session pushed.
7. **Kaggle Secrets** (defined once per account; attached per notebook). Open any notebook in the
   editor → menu **Add-ons → Secrets** → **+ Add a new secret** (Label, Value). Define: `HF_TOKEN`
   (step 3); `KAGGLE_USERNAME` and `KAGGLE_KEY` (**Settings → API → Create New Token** downloads
   `kaggle.json` with both values; the notebooks' push to `noilai-runs` reads them; as of 2026 the
   same panel also issues an *access token*, the `KAGGLE_API_TOKEN` the `kaggle` CLI reads, see §5);
   `GROQ_API_KEY` (console.groq.com → API Keys; §4); `GITHUB_TOKEN` only if you run without a
   bundle (never needed with `noilai-bundle`); `GEMINI_API_KEY` only after the DD 13.18 decision.
   Every secret has an **Attach to notebook** toggle (as of 2026): turn it on for each notebook that
   needs it. The notebooks report each secret as found / not found and never print a value.
8. **Read the real quota** and send the numbers to the assistant. In the notebook editor's right-hand
   **Notebook / Session options** panel, the **Accelerator** dropdown lists each option with "N hrs
   left this week" and the reset time (as of 2026 this is the quota page; `experiments/quota.yaml`
   assumes 30 GPU-h, 20 TPU-h, reset Saturday 00:00 UTC, all `[UNCERTAIN: verify]`). To learn whether
   CPU sessions count against the GPU hours: note the GPU figure, run a CPU session (accelerator
   **None**) for ~30 min, read it again; record the answer in `experiments/quota.yaml`
   (`cpu_sessions_count_against_gpu_quota`) and the real hours and reset day in the same file.

## 1. GPU session (`notebooks/kaggle_eval_t4.ipynb`)

1. kaggle.com → **Code → + New Notebook**. In the editor: **File → Import Notebook → Upload** → drag
   `notebooks/kaggle_eval_t4.ipynb` from the commit you bundled → **Import**. Rename the notebook
   (title at top left) to the line it will run, e.g. `noilai-smoke` or `noilai-pilot-t1`.
2. Right-hand panel **Session options**: **Accelerator → GPU T4 x2**; **Internet → On**;
   **Persistence → No persistence** (the clone is ephemeral by design; `--resume` works from the runs
   dataset, not from the session); **Environment**: leave the default (cell (c) records the versions).
3. **Input → + Add Input → Your Work** (or search by name) → add the three private datasets
   `noilai-bundle`, `noilai-release` and (from the second session on) `noilai-runs`. They mount at
   `/kaggle/input/noilai-bundle/noilai-main.bundle`, `/kaggle/input/noilai-release/...` and
   `/kaggle/input/noilai-runs/runs/...`, which are the parameters cell's defaults.
4. **Add-ons → Secrets**: attach `HF_TOKEN`, `KAGGLE_USERNAME`, `KAGGLE_KEY` (step 0.7).
5. Edit the **parameters cell** (the first code cell; nothing else). Always set
   `ACCOUNT_HOLDER_ROLE = "<role>"` (step 0.1) and `REPO_REF` to the bundled commit hash for any run
   that may reach the paper (`"main"` resolves to the bundle's `main`; the manifest records the hash
   either way). `CREATE_DATASET = True` on the very first session only (it creates `noilai-runs`;
   `RUNS_RESTORE_DIR` may stay as it is: a missing input prints "nothing to restore"). Then, per job:
   * **Smoke test** (the first session; `smoke_20` is the only kind of line allowed a `--limit`, and
     the only kind that runs without pinned revisions):
     `RUN_ID = "smoke_20"`, `MODELS = []` (every T4 model: 14 entries, each on its configured `t4` or
     `2xt4` hardware; or a list such as `["gemma-3-1b-it"]` for the quickest first try),
     `SMOKE_RUN_IDS = ["smoke_20"]`, `SMOKE_MODEL = "gemma-3-1b-it"` (cell (e) runs it first; cell (f)
     then runs the whole smoke line). `VLLM_VERSION = "0.30.0"` and `INSTALL_MODE = "venv"` stay until
     the smoke pins them; a model that fails is reported `failed (<rc>)` and named, the loop goes on.
   * **Gate 1 pilots** (dev items; three models `gemma-3-1b-it`, `qwen3.5-2b`, `phogpt-4b-chat`;
     `phogpt-4b-chat` runs on HF transformers, not vLLM). One line per session (the T4 notebook runs a
     single `RUN_ID`): session A `RUN_ID = "pilot_t1_200"`, session B `RUN_ID = "pilot_xcopa_200"`,
     both with `MODELS = []`, `SMOKE_RUN_IDS = ["smoke_20"]` (or `[]` once the smoke has passed, to save
     the minutes). These are NON-smoke lines: a self-hosted model whose `revision` is `null` is
     `skipped: revision not pinned` (DD 7.1), so run §3's `pin` job and the apply step first and bundle
     the pinned `configs/models.yaml`; the fallback `ALLOW_UNPINNED_REVISION = True` is a rehearsal
     whose manifests record `revision: null` and must be re-run after the pin.
   * **Exploratory dev lines** (`configs/run_plan_exploratory.yaml`; never a paper table):
     `PLAN_PATH = "configs/run_plan_exploratory.yaml"`, `SMOKE_RUN_IDS = []` (that plan has no smoke
     line; cell (e) then runs nothing), `RUN_ID = "floor_pilot_dev"` (five smallest models, T1 + T3
     forced choice, 400 dev items) or `RUN_ID = "throughput_dev"` (one model per backend/precision
     class, 300 dev items; `gemma-3-4b-it` is a `2xt4` entry and runs because `SESSION_HARDWARE =
     "2xt4"`), `MODELS = []`. The derived files `pilot_t1t3_dev` / `throughput_t1_300` have `sha256:
     null` until the author records the hashes cell (d) prints the first time; the ledger marks those
     units `hash_verified = n/a` until then. Pinned revisions apply here too.
   * Everything else (`E1_main`, `E1_explicit_input`, every `E3_*`, the ablations, `reasoning_500`,
     `E1_attested`, `E3_scope_item`, `E3_engine_hf`) reads a canary-bearing test or core file or is
     confirmatory, and the driver reports every model `skipped: gate: ...` until
     `experiments/gates.yaml` carries the registration link and date and the `qu` and `i/y` decisions
     (CLAUDE.md "Binding documents and gates"; the file travels in the bundle). Do not launch them
     before that; `MAX_SESSION_HOURS = 9.0` and `PUSH_EVERY_MINUTES = 30` stay (DD 7.6).
6. Top right: **Save Version** → **Version Type: Save & Run All (Commit)** → **Save**. The version
   runs in a fresh 12-hour session with your parameters; close the editor if you like.
7. Watch it: the editor shows the running version's log in the bottom **Logs** pane; from any Kaggle
   page the bottom-left **View Active Events** tray (as of 2026) lists the session with **Stop
   session**; the notebook's viewer page has a **Logs** tab per version. Expect, in order: (a) the two
   T4s and the free space at `/kaggle/working` (~20 GB), (b) `HEAD <hash>` equal to
   `dist/noilai-main.bundle.commit`, (b')
   `restored {...}` or "nothing to restore", (c) ~10 min of pip, (d) `item files to verify: [...]`
   followed by one JSON summary per file, (e) `smoke_20 gemma-3-1b-it -> ok`, (f) one `[done ]
   <model>: ok, H h, N new outputs` line per model with a dataset push after each, (g) the final push,
   (h) `compute log: ... checklist C1`.
8. **Done** looks like: the version carries a green tick ("Successfully ran"); the run cell's JSON
   lists every model with `"status": "ok"` (or a named `skipped: ...` / `refused: ...` /
   `failed (<rc>)`, each a sentence you can read); the version's **Output** tab lists
   `noilai_runs_out/runs/<RUN_ID>__<model>/outputs.jsonl` and `manifest.json` and
   `noilai_runs_out/compute_log.csv`; the dataset `noilai-runs` shows a new version named
   `<RUN_ID> @ <8-char HEAD>`. A session killed at the 12-hour wall keeps the last 30-minute push;
   re-run the same notebook with `noilai-runs` attached and `--resume` continues at the first undone
   row (cell (b') prints the restored run directories).

## 3. CPU-only jobs that need the hub (`scripts/kaggle_cpu_jobs.py`)

The tokenizer audits of all 21 tokenizers, the per-item tokenization covariates (E2's identifiability
floor) and the panel pin need `huggingface.co` but no GPU, so they run in a CPU session (free of GPU
quota unless step 0.8 says otherwise).

1. **Code → + New Notebook** (a blank one; nothing to import). **Session options**: **Accelerator →
   None**, **Internet → On**, **Persistence → No persistence**. **Add Input**: `noilai-bundle`,
   `noilai-release`, and `noilai-runs` if it exists. **Add-ons → Secrets**: attach `HF_TOKEN`,
   `KAGGLE_USERNAME`, `KAGGLE_KEY`.
2. Paste this as the first cell (plain Python; replace `<role>` only) and run it, or **Save & Run
   All**. It clones the bundle, installs the project, exports the token, fetches the third-party
   resources (SHA-256 against `data/HASHES.json`), runs the three sub-jobs in order and writes the
   report that names every output with its hash:

   ```python
   import os, subprocess, sys
   from kaggle_secrets import UserSecretsClient
   subprocess.run(["git", "clone", "/kaggle/input/noilai-bundle/noilai-main.bundle", "/kaggle/working/repo"], check=True)
   os.chdir("/kaggle/working/repo")
   subprocess.run(["git", "checkout", "--detach", "origin/main"], check=True)   # or the bundled commit hash
   subprocess.run([sys.executable, "-m", "pip", "install", "-q", "-e", ".", "transformers", "sentencepiece", "huggingface_hub"], check=True)
   os.environ["HF_TOKEN"] = UserSecretsClient().get_secret("HF_TOKEN")          # exported, never printed
   subprocess.run([sys.executable, "scripts/fetch_resources.py"], check=True)
   rc = subprocess.run([sys.executable, "scripts/kaggle_cpu_jobs.py", "all",
                        "--release-dir", "/kaggle/input/noilai-release/v0.3",     # or /kaggle/input/noilai-release for a flat upload
                        "--report", "data/audit/cpu_jobs_report.json"]).returncode
   print("cpu jobs exit code", rc, "(1 = a whole job could not run; see the report)")
   ```

   Sub-jobs, runnable one at a time by replacing `"all"`: `audit-tokenizers` (→ `data/audit/<name>.json`
   + `<name>_rows.csv` per tokenizer), `audit-items` (→ `data/audit/items_<tokenizer>__<key>.jsonl` for
   `noilai_main`, `noilai_core`, `noilai_dev`), `pin` (→ `experiments/panel_pins.json`; exit 1 means some
   `hf_id` did not resolve: the JSON names which, with `gated` / `not_found` / `error`).
3. Hand the outputs back through `noilai-runs` with a second cell. A dataset version is a full
   snapshot, so the existing `runs/` tree is staged again next to the new files (the GPU notebooks'
   restore cell reads only `runs/` and `compute_log.csv` and ignores `audit/` and `panel_pins.json`):

   ```python
   for name in ("KAGGLE_USERNAME", "KAGGLE_KEY"):
       os.environ[name] = UserSecretsClient().get_secret(name)
   cmd = [sys.executable, "scripts/kaggle_dataset.py", "--src", "/kaggle/input/noilai-runs/runs",
          "--src", "/kaggle/input/noilai-runs/compute_log.csv", "--src", "data/audit",
          "--src", "experiments/panel_pins.json", "--dest", "/kaggle/working/noilai_runs_dataset",
          "--slug", "noilai-runs", "--message", "cpu jobs: audits + pins"]
   subprocess.run(cmd + (["--create"] if not os.path.exists("/kaggle/input/noilai-runs") else []), check=True)
   ```

   (Sources that do not exist are reported `[skip]` and left out, so the same cell works before
   `noilai-runs` exists.) The files are also under the version's **Output** tab
   (`repo/data/audit/`, `repo/experiments/panel_pins.json`) for a download by hand.
4. Back home (§5): `python3 scripts/pin_panel.py --apply --from experiments/panel_pins.json` writes the
   hashes into `configs/models.yaml` (`--partial` keeps unresolved entries null; `--dry-run` shows the
   plan), commit `configs/models.yaml` + the JSON together, `data/audit/*.json` and `*_rows.csv` (the
   `items_*.jsonl` files stay local, git-ignored), then `make bundle` and a new `noilai-bundle` version
   so that the pinned panel reaches the next GPU session.

## 4. API runs (`notebooks/api_runs.ipynb`; Groq only)

   (`providers.gemini.terms.trains_on_inputs: true`), so the driver refuses it on every core-derived

## 5. Hand-back: getting results to the analysis side

(a) **Preferred: let the assistant pull from Kaggle.** In the cloud session's title bar open the
cloud environment menu → **Edit** → **Network access**: add `www.kaggle.com`, `huggingface.co` and
`cdn-lfs.huggingface.co` under **Allowed domains** with **Allow package managers** left ticked (the
steps are at https://code.claude.com/docs/en/cloud-environments#network-access). In the same dialog,
under **Network secrets** (or as an environment variable where that section is absent), store a Kaggle
access token (Settings → API, step 0.7) as `KAGGLE_API_TOKEN`; alternatively the token file
`~/.kaggle/access_token`, or `KAGGLE_USERNAME` + `KAGGLE_KEY`. A new session picks it up and the
assistant runs `kaggle datasets download <kaggle-user>/noilai-runs -p data/runs_download --unzip` and
the same for `noilai-release` (needed to score), then scores, ingests and updates the meter itself.
Never paste a token into the chat.

(b) **Otherwise, by hand.** On the Kaggle dataset page of `noilai-runs` click **Download** (top right,
as of 2026; a zip of the latest version) and unzip it into a directory outside the repository, e.g.
`~/noilai-runs-2026-10-20/` holding `runs/` and `compute_log.csv`. Then, on a machine with the frozen
`data/release/v0.3/` files (the author's), from the repository root:

1. Score every finished run directory: `for d in ~/noilai-runs-2026-10-20/runs/*/; do python3
   scripts/score_run.py --run "$d"; done` (writes `scores.jsonl` + `summary.json` next to each
   `outputs.jsonl`; the item file is resolved by the manifest's hash under `data/release/*/`).
2. `python3 scripts/ledger.py ingest --runs ~/noilai-runs-2026-10-20/runs` — updates
   `experiments/ledger.csv` (status, item-file hash gate, row counts) and copies `summary.json` and a
   manifest excerpt into `experiments/aggregates/<run_id>__<model>/`; exit 1 names a hash mismatch.
3. Merge the compute log: `data/compute_log.csv` in the repository is replaced by the downloaded
   `compute_log.csv` when the session chain restored it every time (the Kaggle copy is then the full
   campaign log); otherwise append the new rows. Check with `python3 scripts/compute_log.py totals`.
4. `python3 scripts/progress.py` — rewrites the meter block of `STATUS.md` (never type a number into it).
