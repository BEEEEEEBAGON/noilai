# RUNBOOK — running the compute chunks on Kaggle by hand (2026-10-07)

The assistant's machine has no Kaggle token and cannot reach `www.kaggle.com` or `huggingface.co`
(BLOCKED.md), so every session is launched by the author in the Kaggle web UI and the results come back as
a private Kaggle dataset. There is ONE plan: `configs/compute_chunks.yaml`, 31 chunks `c01_cpu_t0` …
`c31_tpu_t5`, one Kaggle session each, generated by `scripts/plan_chunks.py` together with the notebooks
`notebooks/chunks/<id>.ipynb` and the chunk table of `docs/COMPUTE_PLAN.md` §4 (order, tiers, estimates,
quota readings; never retyped here). `docs/COMPUTE_PLAN.md` §5 gives the windows, §7 the short checklist this
file expands. The ledger (`experiments/ledger.csv`) and the meter (`STATUS.md`) track the same chunk units;
`STATUS.md` "Next chunk per queue" names the chunk to import next on each queue (cpu / gpu / tpu). In every
notebook the **first code cell (the parameters cell) is the only cell to edit**; a chunk notebook's header says
"do not edit" because `JOBS` and the other presets are the plan. Kaggle UI labels are given as they read in
2026; where a label may have moved it is marked "(as of 2026)".

## 1. A chunk session (every chunk follows this)

1. Pick the chunk: `STATUS.md` "Next chunk per queue" names one id per queue; `configs/compute_chunks.yaml`
   gives its `queue`, `window`, `hours` and `jobs`; the table in `docs/COMPUTE_PLAN.md` §4 shows the order. Never
   run a chunk outside its window (`now - 25 Oct` for `c01`–`c07`; `after the stage-2 commit (DD 8.8) - 22 Nov`
   for `c08`–`c31`).
2. kaggle.com → **Code → + New Notebook** → **File → Import Notebook → Upload** → drag
   `notebooks/chunks/<id>.ipynb` from the commit you bundled → **Import**. Rename the notebook (title at top left)
   to the chunk id.
3. **Session options**: **Accelerator** per queue: cpu → **None**; gpu → **GPU T4 x2**; tpu → **TPU VM v5e-8**
   (as of 2026). **Internet → On**. **Persistence → No persistence** (the clone is ephemeral; `--resume` works from
   the runs dataset). **Environment**: the default (cell (c) records the versions).
4. **Input → + Add Input → Your Work**: `noilai-bundle`, `noilai-release` and (from the second session on)
   `noilai-runs`. They mount at `/kaggle/input/noilai-bundle/noilai-main.bundle`,
   `/kaggle/input/noilai-release/...` and `/kaggle/input/noilai-runs/...`, the parameters cell's defaults.
5. **Add-ons → Secrets**: attach `HF_TOKEN`, `KAGGLE_USERNAME`, `KAGGLE_KEY`.
6. Edit the **parameters cell** and only these settings: `ACCOUNT_HOLDER_ROLE = "<role>"` (step 0.1);
   `REPO_REF` = the bundled commit hash for any run that may reach the paper (`"main"` resolves to the bundle's
   `main`; the manifest records the hash either way); `CREATE_DATASET = True` on the very first session only;
   the push settings (`PUSH_DATASET`, `PUSH_AFTER_EACH_MODEL`, `PUSH_EVERY_MINUTES`, `KAGGLE_DATASET_SLUG`) if
   your dataset is named otherwise. **Never** `JOBS`, `MODE`, `MODELS`, `RUN_ID` / `RUN_IDS`, `RUN_LABEL`,
   `VERIFY_ITEM_KEYS`, `SMOKE_RUN_IDS`, `PLAN_PATH`, `ALLOW_UNPINNED_REVISION` or `FORCED_CHOICE`: they are the
   plan (`scripts/plan_chunks.py`); a change goes through the generator and a new `--write`, not through a cell.
   A version or package pin that turns out wrong (`VLLM_VERSION`, `VLLM_TPU_PACKAGE`, `TRANSFORMERS_OVERRIDE`)
   is reported to the assistant and fixed in `scripts/kaggle_build_notebooks.py` for every notebook at once.
7. Top right: **Save Version → Version Type: Save & Run All (Commit) → Save**. The version runs in a fresh
   session with your parameters; close the editor if you like.
8. Watch it: the editor's bottom **Logs** pane; from any page the bottom-left **View Active Events** tray (as of
   2026) lists the session with **Stop session**; the viewer page has a **Logs** tab per version. Expect, in
   order: (a) the device and the free space at `/kaggle/working`, (b) `HEAD <hash>` equal to
   `dist/noilai-main.bundle.commit`, (b') `restored {...}` or `nothing to restore`, (c) the install,
   (d) `plan: configs/run_plan.yaml with runs [...]` and `item files to verify: [...]` with one JSON summary per
   file, (f) one `[plan ]` / `[done ]` block per (run, model) and a JSON list with `status`, `hours`,
   `new_outputs`, (f') one `check_run.py` JSON per run directory, (g) `outputs copied to ...` and the dataset
   push, (h) the compute-log totals and `log copied to ...`.
9. **Done** looks like: a green tick ("Successfully ran"); every job of the JSON list has `"status": "ok"`;
   the version's **Output** tab lists `noilai_runs_out/runs/<run>__<model>[__<tag>]/` holding `outputs.jsonl`,
   `manifest.json`, `scores.jsonl`, `summary.json`, `stats.json`, `results_hashes.json`, plus
   `noilai_runs_out/compute_log.csv`; the dataset `noilai-runs` shows a version named `<chunk id> @ <8-char
   HEAD>` (the per-model versions in between read `<run>/<model> ok @ ...`). Any other status is a sentence:
   `skipped: gate: ...` (§1b), `skipped: revision not pinned ...` (§3), `skipped: session budget ...`,
   `refused: ...`, `failed (<rc>)`.
10. **Resume**: a session killed at the wall keeps its last push. Re-run the SAME notebook (same inputs,
    `noilai-runs` attached): cell (b') restores the run directories, every job continues at its first undone
    row, finished rows are skipped. Repeat until every job is `ok`, then hand back (§5); `STATUS.md` then
    names the next chunk.

### 1a. CPU chunks `c01_cpu_t0` – `c04_cpu_t0` (the first real run and the Gate 1 pilot; memo N10, N11)

- `c01_cpu_t0` is **the first real run**: the smoke line on one model through the HF backend in float32 on a
  session with **Accelerator → None** (no GPU quota). Expected well under an hour (RL-2026-10-01-06). It is also
  the first session, so `CREATE_DATASET = True` here and `noilai-runs` is not attached yet (b' prints `nothing
  to restore`). `c02`–`c04` are the Gate 1 pilot, one model per session (`MODE = 'pilot'`: the smoke line again,
  which `--resume` skips, then `pilot_t1_200` and `pilot_xcopa_200`); their worst-case hours are in the chunk
  table (the generator caps a CPU chunk at 10 h; `MAX_SESSION_HOURS = 10.0`).
- Cell (c') **pins the session's model** before anything runs: `pin_panel.py --names <MODELS> --apply --partial
  --out /kaggle/working/noilai_runs_out/panel_pins.json` resolves the model's hub revision, tokenizer and
  chat-template hashes and applies the hash to the CLONE's `configs/models.yaml` (`--partial`: the other panel
  entries stay as they are). A licence the `HF_TOKEN` account has not accepted fails here, with the reason. The
  pins file is saved with the version's **Output** tab but NOT pushed to `noilai-runs`; download it from the
  Output tab when you want it at home (`pin_panel.py --apply --from <file> --partial`, §3 step 4). The
  repository's `configs/models.yaml` is never written by a notebook.
- `MIN_RAM_GB = 12` is a check (cell (a)), not a setting to lower. `TRANSFORMERS_OVERRIDE` is for `c04` only
  (the PhoGPT entry's MPT remote code may fail under the pinned transformers 5.x; the value is `[UNCERTAIN:
  verify]` and is recorded in the environment file): if `c04` fails at model load, tell the assistant the error
  and the version that works; it is then set in the generator (§1 step 6).
- `FORCED_CHOICE = True` adds the EXPLORATORY T1 forced choice to the T1 pilot line
  (`docs/FORCED_CHOICE_EXPLORATORY.md`); it is pre-specified and never a paper table. Leave it.
- Every CPU run directory carries the tag `__cpu` (`smoke_20__gemma-3-1b-it__cpu`, …): a T4 run of the same
  line keeps its own directory, so the smoke week can compare the two row by row. Never remove the tag.

## 3. CPU hub jobs: tokenizer audits, item audits, the whole-panel pin (`scripts/kaggle_cpu_jobs.py`)

Deadline **25 Oct** (panel freeze, memo row 9). Required before `c05_gpu_t0` and before ANY non-smoke GPU / TPU
line (the driver skips an unpinned model: `skipped: revision not pinned`); do it in the smoke week so that
`c06` / `c07` run on the pinned panel. The audits of every tokenizer and the per-item tokenization covariates
need the hub but no GPU, so everything runs in one CPU session.

1. **Code → + New Notebook** (blank). **Session options**: **Accelerator → None**, **Internet → On**,
   **Persistence → No persistence**. **Add Input**: `noilai-bundle`, `noilai-release`, and `noilai-runs` if it
   exists. **Add-ons → Secrets**: `HF_TOKEN`, `KAGGLE_USERNAME`, `KAGGLE_KEY`.
2. Paste this as the first cell (replace `<role>` with nothing: the audits record no manifest) and **Save & Run
   All**. It clones the bundle, installs the project, exports the token, fetches the third-party resources
   (SHA-256 against `data/HASHES.json`), runs the three sub-jobs in order and writes a report naming every
   output with its hash:

   ```python
   import os, subprocess, sys
   from kaggle_secrets import UserSecretsClient
   subprocess.run(["git", "clone", "/kaggle/input/noilai-bundle/noilai-main.bundle", "/kaggle/working/repo"], check=True)
   os.chdir("/kaggle/working/repo")
   subprocess.run(["git", "checkout", "--detach", "origin/main"], check=True)   # or the bundled commit hash
   subprocess.run([sys.executable, "-m", "pip", "install", "-q", "-e", ".", "transformers", "sentencepiece", "huggingface_hub"], check=True)
   os.environ["HF_TOKEN"] = UserSecretsClient().get_secret("HF_TOKEN")          # exported, never printed
   subprocess.run([sys.executable, "scripts/fetch_resources.py"], check=True)
   rc = subprocess.run([sys.executable, "scripts/kaggle_cpu_jobs.py", "all",
                        "--release-dir", "/kaggle/input/noilai-release/v0.3",     # or /kaggle/input/noilai-release for a flat upload
                        "--report", "data/audit/cpu_jobs_report.json"]).returncode
   print("cpu jobs exit code", rc, "(1 = a whole job could not run; see the report)")
   ```

   Sub-jobs, runnable one at a time by replacing `"all"`: `audit-tokenizers` (→ `data/audit/<name>.json` +
   `<name>_rows.csv` per tokenizer; the census verdicts move a normalizing family's E3 jobs to tier 5 at the next
   `plan_chunks.py --write`), `audit-items` (→ `data/audit/items_<tokenizer>__<key>.jsonl` for `noilai_main`,
   `noilai_core`, `noilai_dev`), `pin` (→ `experiments/panel_pins.json`, every self-hosted entry plus the
   open-weight API entries for their tokenizer record; exit 1 = incomplete: the JSON says which entry and why,
   `gated` / `not_found` / `error` / `checkpoint_unchosen`).
3. Hand the outputs back: they are under the version's **Output** tab (`repo/data/audit/`,
   `repo/experiments/panel_pins.json`, `repo/data/audit/cpu_jobs_report.json`): download them. (Pushing them into
   `noilai-runs` with `scripts/kaggle_dataset.py --src data/audit --src experiments/panel_pins.json ...` also
   works but makes the next session's restore cell copy `audit/` under `data/runs/`: harmless, untidy; avoid.)
4. **Back home**, in the repository: `python3 scripts/pin_panel.py --apply --from experiments/panel_pins.json
   --dry-run` shows the plan. A full apply is **refused** while a panel entry waits for a quantization checkpoint
   (`quantization.method` set, `checkpoint: null`, not bitsandbytes: five panel entries today, `hf_id_status:
   checkpoint_unchosen` in the JSON): choose those checkpoints in `configs/models.yaml` (the panel-freeze
   decision, memo row 9), re-run the `pin` job, then apply; or apply what resolved now with `--partial` (the
   rest stays null and is skipped by the driver until pinned). `--force` overwrites a different existing pin,
   never by default. Commit `configs/models.yaml` and `experiments/panel_pins.json` TOGETHER, with
   `data/audit/*.json` and `*_rows.csv` (`items_*.jsonl` stay local, git-ignored); then `make bundle` and a new
   `noilai-bundle` version so the pinned panel reaches the next session.

## 6. What never to do

1. Never make `noilai-release`, `noilai-runs` or `noilai-bundle` public, and never attach a public dataset in
   their place: the test split is gated and every output quotes test items (DD 11.1).
2. Never paste a token, key or password into a cell, a parameters value or the chat; secrets live in **Add-ons →
   Secrets** and reach the code only through `os.environ`.
3. Never edit a chunk notebook's `JOBS`, `overrides`, `MODE`, `MODELS`, `RUN_ID(S)`, `RUN_LABEL`,
   `VERIFY_ITEM_KEYS` or `PLAN_PATH`, and never a cell other than the parameters cell on Kaggle: the chunk plan is
   `configs/compute_chunks.yaml`; changes go through `scripts/plan_chunks.py` / `scripts/kaggle_build_notebooks.py`
   and a new `--write`, so that `tests/test_cloud.py`'s drift check still passes.
4. Never launch a tier ≥ 1 chunk (`c08`–`c31`) or any API line before the stage-2 commit (DD 8.8) and before the
   author has recorded the registration link, date and decisions in `experiments/gates.yaml`; never fill that file
   with placeholder values to get past the gate; never run `E3_*` test-split lines before 8 November 2026.
5. Never mix CPU and GPU rows of one line in one run directory: the `__cpu` tag (and `__p0p1` / `__p2`) is what
   keeps them apart; never rename or merge run directories by hand.
6. Never send core or test items to Gemini's free tier or any API tier whose terms allow training on inputs;
   never set `paid_key_data_use_opt_out: true` without a verified opt-out recorded by the author; never send the
   sealed split, a vulgar-flagged item, the canary or any validator or participant data to any API (DD 11.2).

   notebook), never record a quota reading there (step 0.8), never rebuild the frozen release, and never commit
